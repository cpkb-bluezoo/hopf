Telemetry

Connection hooks enqueue logs; HTTP request traces and metrics attach at the Stream handler — like Gumdrop.

TelemetryHook (connections)

pub trait TelemetryHook: Send + Sync {
    fn on_accept(&self, peer: SocketAddr) {}
    fn on_dial(&self, peer: SocketAddr) {}
    fn on_close(&self, peer: SocketAddr) {}
    fn on_error(&self, peer: Option<SocketAddr>, msg: &str) {}
}

Attach via Runtime::start_with_telemetry or Composition::telemetry. Accept path reports ACL/rate-limit denials through on_error; connections call on_close / on_error on teardown.

NopTelemetry discards everything. Hook implementations must not perform I/O on the accept or reactor threads.

HTTP request traces & metrics

Instrument at the ServerHandler layer with InstrumentedServerFactory — not at TCP accept. Config flags traces_enabled / metrics_enabled mirror Gumdrop TelemetryConfig.

use std::sync::Arc;
use hopf_otel::{InstrumentedServerFactory, OtelConfig, TelemetryPipeline};

let pipeline = TelemetryPipeline::start(
    OtelConfig::new("my-service")
        .with_otlp_endpoint("http://127.0.0.1:4318")
        .with_traces(true)
        .with_metrics(true),
)?;

let app: Arc<dyn ServerHandlerFactory> = Arc::new(HelloFactory);
let factory = Arc::new(InstrumentedServerFactory::new(app, &pipeline));
// pass `factory` to CleartextHttpEndpoint / AlpnHttpEndpoint / …

let rt = Runtime::start_with_telemetry(config, Some(pipeline.hook()))?;

Per request the factory:

  • continues from inbound traceparent (or starts a new SERVER span named HTTP {method})
  • injects response traceparent
  • records http.server.requests, active_requests, request.duration, sizes

Handlers read the active context with ServerWriter::traceparent() and pass it to outbound clients:

fn headers(&mut self, response: &mut dyn ServerWriter, headers: &Headers) {
    let tp = response.traceparent().map(str::to_owned);
    // … later, when writing an outbound request:

Helpers: inject_traceparent, with_traceparent, with_trace (Gumdrop HTTPClient.setTrace parity).

hopf-otel exporters

Crate hopf-otel provides TelemetryPipeline:

  • OTLP/HTTP — batched protobuf POST to /v1/logs, /v1/traces, /v1/metrics
  • JSONL — OTLP JSON Lines file appenders per signal
use hopf_otel::{OtelConfig, TelemetryPipeline};

let pipeline = TelemetryPipeline::start(
    OtelConfig::new("my-service")
        .with_otlp_endpoint("http://127.0.0.1:4318")
        .with_jsonl_logs("/var/log/hopf/logs.jsonl")
        .with_jsonl_traces("/var/log/hopf/traces.jsonl")
        .with_jsonl_metrics("/var/log/hopf/metrics.jsonl"),
)?;

Events are queued with a bounded channel (overflow drops). Encoding and network/file I/O happen only on the hopf-otel-export thread.
