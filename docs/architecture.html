Architecture

Hopf is a **thread-per-core** (TPC) networking framework on

Hopf is a thread-per-core (TPC) networking framework on mio. Listen and dial are equal bindings on one Runtime. Codecs are incremental push parsers (chunked ingress, handler egress) — not a Tokio/Hyper stack.

Process shape

Composition / script
       │
       ├── add_tcp_listener / remove_binding  → Accept loop
       └── connect / dial                     → worker reactors
Accept ──affinity──► Reactor 0 … N
                         │
                      Endpoint
                         │
                  ProtocolHandler
                         │
              (HTTP Stream | TLS | DNS | …)
  • Accept loop — binds sockets, applies ACL/rate limits, round-robins new connections onto workers.
  • Worker reactor — owns connection affinity for life; timers, TLS I/O, UDP (DNS), execute hops.
  • StorageExecutor — blocking filesystem / mailbox work off the reactor; results hop back via Endpoint::execute / ConnHandle.

Endpoint vs ProtocolHandler

Type Role
Endpoint Transport face: send, close, start_tls, pause/resume, peer addr
ProtocolHandler Application/protocol FSM: connected, receive, disconnected, error

HTTP adapters (H1Endpoint, H2Endpoint, …) are ProtocolHandlers that drive ServerHandler / ClientHandler on an HTTP Stream.
