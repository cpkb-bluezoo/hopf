Mailbox

Crate hopf-mailbox: mailbox storage SPI (Gumdrop org.bluezoo.gumdrop.mailbox port) — Maildir++ and mbox backends with SEARCH, flags, and optional .gidx indexing. This is not an IMAP wire server; an IMAP protocol crate would sit on top of these traits.

SMTP local delivery is also not wired stock — see SMTP limitations and append from a custom MessageDataHandler on StorageExecutor.

Standards and layouts

Reference Role
RFC 9051 IMAP SEARCH §6.4.4; system flags
RFC 822 / Internet Message Format Message bytes
Maildir++ Hierarchical folders, :2, flags, COPY/MOVE
mbox Single-file mailbox + .flags sidecar
.gidx Gumdrop-compatible index: v1 headers, v2 body

Architecture

App / future IMAP / SMTP delivery
            │
            ▼
MailboxFactory → MailboxStore → Mailbox
            │
            ├── mbox:  {root}/{user}  + .flags + .gidx
            └── Maildir++: {root}/{user}/ cur|new|tmp + .uidlist …
            │
            └── ALWAYS run search/index I/O on StorageExecutor

Never perform heavy mailbox I/O on a reactor thread.

Backends compared

Capability mbox Maildir++

COPY / MOVE Unsupported Yes

Factories:

  • MboxFactory::new(root).with_index_config(cfg) → path {root}/{user}
  • MaildirFactory::new(root).with_index_config(cfg) → {root}/{user}/

Mailbox API

Typical flow:

use hopf_mailbox::{IndexConfig, MaildirFactory, SearchCriteria};

let factory = MaildirFactory::new("/var/mail")
    .with_index_config(IndexConfig::with_body_indexing());
let mut store = factory.create_store();
store.open("alice")?;
let mut mb = store.open_mailbox("INBOX", false)?; // read_only flag
mb.append_message(rfc822_bytes, &flags, None)?;
let hits = mb.search(&SearchCriteria::text("needle"))?;
mb.close(true)?; // expunge when true

Operations (trait surface): close(expunge), counts/size, messages, read_message, UID / uidvalidity / uidnext, flags / keywords, set/replace flags, append stream, search, copy / move (Maildir).

SEARCH

Criteria include: ALL, system flags, NEW/OLD, KEYWORD, LARGER/SMALLER, BEFORE/ON/SINCE, SENT*, HEADER, BODY, TEXT, UID / sequence sets, MODSEQ, AND / OR / NOT.

BODY / TEXT: use the .gidx body index when body_indexing is enabled; otherwise parse message content on demand.

Indexing

.gidx is Gumdrop-compatible:

  • Version 1 — headers
  • Version 2 — body (when enabled)

Body indexing is off by default (disk cost). Enable with IndexConfig::with_body_indexing().

Storage pool helpers

use hopf_mailbox::pool::{run_on_storage, search_on_storage};

// Prefer these from protocol servers so SEARCH never blocks a reactor:
search_on_storage(&storage, handle, mailbox_arc, criteria, callback);
run_on_storage(&storage, handle, op, callback);

Examples / tests

There is no examples/mailbox binary. Coverage lives in:

cargo test -p hopf-mailbox
# notably: tests/mailbox_integration.rs
#  - mbox append / flags / search
#  - mbox rejects COPY
#  - Maildir body index

Wire from SMTP:

// Prefer LocalDeliveryService for stock local MX; custom handlers can also
// APPEND in MessageDataHandler::message_complete via StorageExecutor:
storage.submit_on(handle, move || {
    let mut store = factory.create_store();
    store.open("alice")?;
    let mut mb = store.open_mailbox("INBOX", false)?;
    mb.append_message(&bytes, &flags, None)?;
    mb.close(false)?;
    Ok(())
}, |result| { /* reply 250/550 via ConnHandle */ });

Limitations

  • Not an IMAP server — storage SPI only (use LocalDeliveryService for SMTP → INBOX).
  • mbox: no hierarchy / COPY / MOVE.
  • Body indexing off by default.
  • Must keep search/index off the reactor (use StorageExecutor).
