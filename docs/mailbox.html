Mailbox

Crate `hopf-mailbox`: IMAP-level **storage** SPI (Gumdrop `org.bluezoo.gumdrop.mailbox` port). Not a full IMAP wire server — an IMAP protocol crate (or custom SMTP delivery) would call these traits.

Crate hopf-mailbox: IMAP-level storage SPI (Gumdrop org.bluezoo.gumdrop.mailbox port). Not a full IMAP wire server — an IMAP protocol crate (or custom SMTP delivery) would call these traits.

Backends

Backend Layout Notes
mbox {root}/{user} + .flags sidecar INBOX only; no COPY/CREATE hierarchy
Maildir++ {root}/{user}/ Hierarchical folders, .uidlist / .keywords, COPY + MOVE, subscriptions

Traits

  • MailboxFactory → MailboxStore (open user, create_mailbox, …)
  • Mailbox: append, flags, fetch, search, copy/move (Maildir), close/expunge

Search criteria align with RFC 9051 §6.4.4 (ALL, flags, dates, HEADER/BODY/TEXT, UID/sequence sets, AND/OR/NOT, MODSEQ, …). Flags: IMAP system flags (\Seen … \Recent) plus Maildir letter mapping.

Indexing

.gidx stores headers, flags, sizes, and dates. Body text is off by default (IndexConfig::body_indexing). TEXT / BODY use the body index when enabled; otherwise they parse message content.

Storage pool

Indexing and searching are blocking filesystem work. Call Mailbox::search / index rebuild only from StorageExecutor (see hopf_mailbox::pool), never on a reactor thread.

let factory = MaildirFactory::new(root)
    .with_index_config(IndexConfig::with_body_indexing());
let mut store = factory.create_store();
store.open("alice")?;
let mut mb = store.open_mailbox("INBOX", false)?;
mb.append_message(rfc822, &flags, None)?;
let hits = mb.search(&SearchCriteria::text("needle"))?;
mb.close(true)?; // expunge \Deleted

SMTP / IMAP

hopf-smtp stock handlers do not deliver into mailboxes yet. Wire a custom MessageDataHandler that append_messages on the storage pool. An IMAP server would sit on top of the same Mailbox / MailboxStore traits.

Integration coverage: crates/hopf-mailbox/tests/mailbox_integration.rs (no examples/mailbox yet).
