AMQP 0-9-1

hopf-amqp is an AMQP 0-9-1 async client (RabbitMQ wire protocol). Client-only: publish opaque bodies and consume via push basic.consume deliveries on the Hopf TPC runtime. There is no broker in this crate. For the unrelated AMQP 1.0 wire protocol, see AMQP 1.0 (hopf-amqp1); the two share only the AMQP magic bytes.

Architecture

AmqpClient::connect
    → Runtime::connect(TcpConnectorConfig)
    → AmqpClientEndpoint (ProtocolHandler)
         protocol header → connection.start/start-ok
         → tune/tune-ok → open/open-ok
         → AmqpClientDriver::on_connection_open
         → channel / topology / basic.* via AmqpClientControl
         ← basic.deliver + content → on_delivery_start/data/complete

Inbound is reactor-driven: socket readable → receive → AmqpFrameParser → driver callbacks. There is no application poll loop.

Client

SPI mirrors MQTT: AmqpClient facade, AmqpClientHandlerFactory, flat AmqpClientDriver / AmqpClientControl.

AmqpClient::new("127.0.0.1", 5672)
    .credentials("guest", "guest")
    .connect(&rt, Arc::new(Factory))?;

On on_connection_open, open a channel (≥ 1), then declare topology, confirm_select, basic_publish, and/or basic_consume.

Automatic recovery

AmqpRecoveringClient::new(client, rt) wraps an AmqpClient and reconnects whenever the connection drops, with exponential backoff (RecoveryPolicy::exponential_backoff(): 1 s doubling to 30 s, unlimited attempts; with_initial_delay, with_max_delay, with_max_attempts). On each reconnect it redeclares every exchange, queue and binding and re-registers every consumer in the order they were first issued. on_connection_open fires only on the first connection; later ones are reported to a RecoveryListener (on_connection_lost, on_reconnecting, on_recovered, on_recovery_failed). The broker's *-ok replies to the replay reach the driver again, so driver callbacks with side effects should be idempotent. connect(factory) returns an AmqpRecoveringHandle; dropping it or calling close() stops further reconnects but does not close a live connection (use AmqpClientControl::connection_close for that).

Messages

Bodies are opaque octets. Basic properties (content-type, content-encoding, headers, delivery-mode, correlation-id, …) travel in the content header; MIME values are conventional, not enforced by the protocol.

Examples

cargo run -p amqp-pub -- 127.0.0.1 5672 demo.queue "hello from hopf"
cargo run -p amqp-consume -- 127.0.0.1 5672 demo.queue

Opt-in broker test: cargo test -p hopf-amqp --features integration.

Limitations

  • No broker / server module
  • No Composition/XML registration
  • Recovery does not re-send publishes that were in flight when the connection dropped
