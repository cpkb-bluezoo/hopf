Auth

TrustPolicy, credential stores, SASL mechanisms, and HTTP Basic/Digest/Bearer.

Crate hopf-auth keeps trust and SASL out of hopf-core. HTTP consumers live in hopf-http.

Types

TypeRole
IdentityMaterialUsername/password, bearer, cert DN/SAN, opaque
PeerContextOptional peer SocketAddr
TrustPolicyevaluate → Accept / Reject
CredentialStoreGumdrop Realm-like backend for SASL / Digest HA1 / tokens / certs
PasswordStoreIn-memory passwords, tokens, and certificate keys
PasswordTrustPolicySimple username/password policy ( demos )

SASL (no GSSAPI)

Mechanisms: PLAIN, LOGIN, CRAM-MD5, DIGEST-MD5, SCRAM-SHA-256, OAUTHBEARER, EXTERNAL.

use hopf_auth::{create_client, create_server, PasswordStore, SaslMechanism, SaslServerOptions};
use std::sync::Arc;

let store = Arc::new(PasswordStore::new().with_user("alice", "s3cret")) as _;
let mut server = create_server(SaslMechanism::ScramSha256, store, SaslServerOptions::default());
let mut client = create_client(SaslMechanism::ScramSha256, "alice", "s3cret", "mail.example");
// drive SaslServer::step / SaslClient::evaluate until Complete

For EXTERNAL, set SaslServerOptions::peer_certificate to the TLS peer fingerprint or DN.

HTTP Basic, Digest, Bearer

  • BasicAuthFactory — TrustPolicy on Authorization: Basic
  • DigestAuthFactory — RFC 7616 MD5 / qop=auth via CredentialStore::digest_ha1
  • BearerAuthFactory — IdentityMaterial::Bearer through TrustPolicy

Client Digest credentials: build_digest_authorization / http_digest::client_authorization.
