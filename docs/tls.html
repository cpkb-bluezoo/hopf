TLS

Crate hopf-tls: rustls glue implementing the hopf-core TLS seam (TlsAcceptor / TlsConnector / TlsSession). Protocol handlers always see plaintext — encryption is under the Endpoint. Supports TLS-from-accept and STARTTLS. ALPN, PEM load, and negotiated SecurityInfo are exposed.

QUIC/TLS 1.3 for HTTP/3 lives primarily in hopf-quic; this crate covers TCP TLS.

Standards

Topic Detail
TLS 1.2 + 1.3 via rustls (ring provider)
ALPN e.g. h2, http/1.1
PEM PKCS#8 / RSA via rustls-pemfile
Patterns TLS-from-accept; STARTTLS (Endpoint::start_tls)

Architecture

TcpListenerConfig / TcpConnectorConfig
        │  SharedTlsAcceptor / SharedTlsConnector
        ▼
hopf-tls (RustlsAcceptor / RustlsConnector / Rustls*Session)
        │
        ▼
Endpoint  →  ProtocolHandler sees plaintext
             security_info() after handshake

Internal types implement core traits; callers use free functions returning SharedTlsAcceptor / SharedTlsConnector (Arc).

Public API

use std::path::Path;
use std::sync::Arc;
use hopf_tls::{
    acceptor, acceptor_from_pem, client_config_from_pem, connector,
    connector_for_certified_pem, connector_from_pem, server_config_from_pem,
};

// Server
let server_cfg = server_config_from_pem(
    Path::new("cert.pem"),
    Path::new("key.pem"),
    &[b"h2", b"http/1.1"],
)?;
let acceptor = acceptor(server_cfg);
// or: acceptor_from_pem(cert, key, alpn)?

// Client
let client_cfg = client_config_from_pem(Path::new("ca.pem"), &[b"h2", b"http/1.1"])?;
let connector = connector(client_cfg);
// or: connector_from_pem(ca, alpn)?

// Dangerous: trust a single leaf (self-signed smoke tests only)
let connector = connector_for_certified_pem(Path::new("leaf.pem"), &[b"http/1.1"])?;
Function Returns Notes
server_config_from_pem Arc<ServerConfig> with_single_cert; no client auth
acceptor / acceptor_from_pem SharedTlsAcceptor
client_config_from_pem Arc<ClientConfig> with_no_client_auth root store
connector / connector_from_pem SharedTlsConnector
connector_for_certified_pem SharedTlsConnector Dangerous single-leaf trust

Sessions support send_close_notify via the core TlsSession trait.

Configuration

There are no numeric knobs in hopf-tls itself. Versions and cipher suites come from rustls defaults (ring, TLS 1.2 + 1.3 enabled).

Input Type Notes
Certificate PEM path &Path Server leaf (+ chain as presented)
Private key PEM path &Path PKCS#8 or RSA
CA PEM path &Path Client trust anchors
ALPN &[&[u8]] e.g. b"h2", b"http/1.1"

Cargo features

Feature Effect
(default) PEM helpers + rustls glue
integration Runtime smoke tests

Wiring listeners and connectors

use hopf_core::TcpListenerConfig;

// TLS-from-accept (HTTPS, implicit FTPS/SMTPS, …)
let cfg = TcpListenerConfig::new(addr, factory)
    .with_tls(acceptor);

// Cleartext first, then STARTTLS (SMTP, explicit FTPS, …)
let cfg = TcpListenerConfig::new(addr, factory)
    .with_starttls_acceptor(acceptor);

Client dial:

use hopf_core::TcpConnectorConfig;

let cfg = TcpConnectorConfig::new(addr, factory)
    .with_tls(connector, "server.example.com");

Protocol crates:

  • FTP — FtpConfig::with_tls / implicit_ftps
  • SMTP — SmtpConfig::with_tls / implicit_tls
  • HTTP — AlpnHttpEndpoint after TLS ALPN
  • Cookbook: TLS echo

SecurityInfo

After handshake, Endpoint::security_info() reports (via core SecurityInfo): secure flag, ALPN protocol, TLS protocol version, cipher suite. Handlers may gate AUTH or HTTP/2 on this metadata (ProtocolHandler::security_established).

Examples

cargo run -p tls-echo -- 127.0.0.1:8443 cert.pem key.pem
Package Demonstrates

Limitations

  • Server helpers use with_no_client_auth — no mTLS verification in these convenience APIs.
  • No client-certificate presentation helpers.
  • connector_for_certified_pem is explicitly dangerous (self-signed demos).
  • Cipher / version policy is rustls default — not customizable via Hopf knobs.
  • QUIC crypto is configured in hopf-quic, not here.
