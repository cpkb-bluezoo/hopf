WebSocket

Crate hopf-websocket: RFC 6455 framing and HTTP upgrade helpers on top of hopf-http upgrade seams. Supports HTTP/1.1 101 Upgrade, HTTP/2 Extended CONNECT (RFC 8441), and HTTP/3 Extended CONNECT (RFC 9220).

Both roles share one framing engine (WsFrameParser, role-aware masking) and one event SPI (WsEventHandler). The accepting side plugs in as an HTTP ServerHandlerFactory (WebSocketFactory); the dialling side uses WebSocketOpening from a ClientHandler and installs WsUpgradeHandler::client through ClientWriter::upgrade (see Client role). Framing is push-incremental and split-feed safe.

        │  upgrade() / Extended CONNECT
        ▼

        │
        ├── WsFrameParser (role-aware masking)
        └── WsEventHandler callbacks
                │
                └── WsSession send_* helpers

Wire as a normal HTTP ServerHandlerFactory:

use hopf_websocket::{EchoFactory, WebSocketConfig, WebSocketFactory};

let events = EchoFactory;
let ws = WebSocketFactory::new(events, WebSocketConfig::default());
// use `ws` as Arc<dyn ServerHandlerFactory> under CleartextHttpEndpoint / AlpnHttpEndpoint

Handshake

HTTP/1.1

Helpers: is_h1_websocket_upgrade, validate_h1_upgrade → key, calculate_accept, websocket_accept_headers, generate_key / create_upgrade_request / validate_upgrade_response / WebSocketOpening (client).

Successful upgrade yields 101 with Sec-WebSocket-Accept. Clients must run validate_upgrade_response (or WebSocketOpening::validate_response) on that 101 before installing WsUpgradeHandler::client.

HTTP/2 / HTTP/3

is_extended_connect_websocket / websocket_connect_response_headers - successful Extended CONNECT yields 200 and then WebSocket frames on the stream.

Optional WebSocketConfig.subprotocol is echoed only when that token appears in the client's Sec-WebSocket-Protocol offer; otherwise it is omitted.

Origin (RFC 6455 §10.2): default OriginPolicy::AllowList([]) rejects any present Origin with 403 (browsers always send it). Missing Origin is allowed for native clients. Configure with WebSocketConfig::with_allowed_origins([...]) or allow_any_origin() for demos.

Client role

A dialling application writes an ordinary ClientHandler and dials with connect_http (or connect_https offering only http/1.1, since the request is an HTTP/1.1 Upgrade). WebSocketOpening generates the key, writes the request and validates the 101; the WebSocket session then starts on the same connection:

struct WsDial { opening: WebSocketOpening, events: Option<Box<dyn WsEventHandler>> }

impl ClientHandler for WsDial {
    fn start(&mut self, request: &mut dyn ClientWriter) {
        self.opening.write_request(request, "/chat", "example.com");
    }
    fn switching_protocols(&mut self, request: &mut dyn ClientWriter, headers: &Headers) {
        if self.opening.validate_response(headers).is_err() {
            return; // not a valid RFC 6455 opening: do not enter the session
        }
        let conn = request.conn_handle();
        let events = self.events.take().unwrap();
        request.upgrade(Box::new(WsUpgradeHandler::client(events, 1 << 20, conn)));
    }
    fn response_headers(&mut self, _: &mut dyn ClientWriter, _: &Headers) { /* refused: no 101 */ }
    fn response_complete(&mut self, _: &mut dyn ClientWriter) {}
}

Outbound frames from the client are masked with a fresh random key per frame; inbound frames must be unmasked.

Framing

Type Role
WsFrameParser Incremental parser; receive(&[u8], &mut dyn WsFrameHandler)
WsFrameHandler Frame callbacks
Opcode Text / Binary / Close / Ping / Pong / Cont
WsRole Server / Client (masking direction)
write_frame Encode a frame into a Vec<u8>
WsFrameError Protocol / size / UTF-8 errors

Role / masking:

  • Server: inbound frames must be masked; outbound must not.
  • Client: reverse (outbound masked via getrandom).

Enforced: RSV bits zero (no extensions), known opcodes, control-frame constraints (FIN, ≤125 bytes), max_payload, valid UTF-8 for text. Default auto-pong on ping.

Event handler SPI

pub trait WsEventHandlerFactory: Send + Sync {
    fn create(&self, path: &str, request_headers: &Headers, conn: ConnHandle) -> Box<dyn WsEventHandler>;
}

pub trait WsEventHandler: Send {
    fn opened(&mut self, session: &mut WsSession<'_>, conn: &ConnHandle);
    fn poke(&mut self, session: &mut WsSession<'_>) {}   // re-entry after off-thread work
    fn wants_streaming(&self) -> bool { false }
    fn text_message(&mut self, session: &mut WsSession<'_>, text: &str) {}
    fn binary_message(&mut self, session: &mut WsSession<'_>, data: &[u8]) {}
    fn text_chunk(&mut self, session: &mut WsSession<'_>, chunk: &str, is_final: bool) {}
    fn binary_chunk(&mut self, session: &mut WsSession<'_>, chunk: &[u8], is_final: bool) {}
    fn ping(&mut self, session: &mut WsSession<'_>, payload: &[u8]); // default auto-pong
    fn pong(&mut self, session: &mut WsSession<'_>, payload: &[u8]) {}
    fn closed(&mut self, session: &mut WsSession<'_>, code: u16, reason: &str) {}
    fn error(&mut self, err: WsFrameError) {}
}

By default a fragmented message (RFC 6455 §5.4) is reassembled and delivered once through text_message / binary_message, so it must fit max_payload. A handler that returns true from wants_streaming instead receives text_chunk / binary_chunk as bytes arrive, without the message ever being held whole; text chunks never split a UTF-8 code point. poke is the WebSocket-layer counterpart of ConnHandle::poke: it gives a handler that offloaded work a chance to finish and reply through session.

WebSocketFactory<F> implements ServerHandlerFactory for any F: WsEventHandlerFactory.

conn is a cloneable hopf_core::ConnHandle for this connection, handed to both create and opened - capture it to hop work back onto this connection's reactor from another thread (e.g. a pub/sub fan-out delivering a message published on a different connection; see hopf-mqtt's WebSocket bridge for a worked example). A plain ConnHandle::send writes straight to the raw transport, bypassing WS framing - wrap the handle with framed_ws_conn_handle (below) before handing it to code that delivers asynchronously; synchronous replies from within a callback should keep using WsSession::send_* instead.

Session send API

impl WsSession {
    fn send_text(&mut self, text: &str);
    fn send_binary(&mut self, data: &[u8]);
    fn send_ping(&mut self, payload: &[u8]);
    fn send_pong(&mut self, payload: &[u8]);
    fn send_close(&mut self, code: u16, reason: &str);
}

send_close_empty() sends a Close frame with no status code. Free helpers: write_text, write_binary, write_ping, write_pong, write_close, write_close_empty (encode into a Vec<u8> for a given WsRole).

Framing a ConnHandle for async delivery

pub fn framed_ws_conn_handle(conn: &ConnHandle, role: WsRole) -> ConnHandle;

Wraps conn so every ConnHandle::send first frames the payload as a WebSocket binary message for role, using hopf_core::ConnHandle::framed (a small additive transform seam on ConnHandle for exactly this case - a protocol layered on top of the raw transport that still needs asynchronous, cross-connection deliveries framed correctly). Use the wrapped handle - not the raw one from create / opened - anywhere a ConnHandle is handed to code that delivers from another connection or thread.

Limitations

  • No permessage-deflate or other extensions (RSV must be zero).
  • Close handling sends a close and marks the session dead; protocol errors emit Close 1002/1007/1009 then tear down the transport/stream.
  • The dialling side has no one-call connect function: a ClientHandler drives WebSocketOpening as shown in Client role, over HTTP/1.1 Upgrade (create_upgrade_request builds the RFC 6455 §4.1 headers). Accepting over H2/H3 Extended CONNECT is supported.
  • Relies on HTTP trailers / Extended CONNECT behaviour of hopf-http for H2/H3.
